## 二、关键机制调研结论

### 1. Agent 循环（claw-code `conversation.rs:run_turn`）
- 循环：用户输入入会话 → 拼请求（system + 全量 messages）→ 调 LLM → 追加 assistant 消息 → **检查迭代上限**（`iterations > max_iterations`）→ 提取 `tool_use` 块 → 无工具调用则结束回合，否则逐个执行工具、每个工具结果追加一条消息 → 回到循环。
- **接口分层**：`ApiClient`（stream 一个请求）与 `ToolExecutor`（execute 一个工具）两个小 trait 把循环和传输/执行解耦 —— 这就是 **Mock LLM 的自然接缝**，我们照搬了该设计。
- 工具结果在 OpenAI 兼容层序列化为 `role: "tool"` 消息；工具参数是 **JSON 字符串**；无 id 时回退 `tool_call_{index}`；参数 JSON 解析失败回退 `{"raw": ...}`。

### 2. 上下文与提示词（claw-code `prompt.rs`）
- System prompt 是**分段向量**（`SystemPromptBuilder`），固定顺序：intro → Output Style → # System → # Doing tasks → # Executing actions with care → 动态边界哨兵 → 环境/项目上下文 → 内存。**静态部分与动态部分分离**，我们照搬（静态 system + 动态数据放 user 消息）。
- 摘要压缩（compaction）与用量统计内置于运行时；我们做简化版（不实现压缩，靠 max_steps 上限）。

### 3. DeepSeek API（官方文档 + 实测）
- 端点 `https://api.deepseek.com`，OpenAI 兼容；模型枚举含 **`deepseek-v4-pro`**（与任务书一致），另有 `deepseek-flash`。
- **推理型模型**：返回 `reasoning_content`，思考也消耗 max_tokens 配额（已实测：max_tokens=32 时 content 为空）。
- **实测确认**：支持标准 `tools`/`tool_calls`（`finish_reason: tool_calls`）与 `response_format: json_object`。
- **关键坑（调研结论 + 实测）**：模型默认开启 thinking；**thinking 开启时 temperature 失效**，且工具调用阶段回传 `reasoning_content` 会引发 400。因此：Plan 阶段（无工具）开 thinking + `reasoning_effort: high`；Generate/Repair 阶段（有工具）**显式 `thinking: {"type": "disabled"}`** 并传 temperature。
- 错误码：401 Key 无效 / 402 余额不足 / 429 限流 / 5xx 可重试；`GET /models` 可做预检。
- 校验方式：`Bearer <key>`；`GET {base}/models` 返回 `data[].id`。

## 三、采纳的设计决策（由综合设计智能体给出）

1. **模块分层**：GUI → Orchestrator（状态机）→ LLM 客户端（Protocol，可换 Mock）/ 工具执行器 / 预处理器 / 检查器 → 磁盘。与第 3 步已实现的 preprocessor 完全吻合。
2. **状态机**：`Preflight → Preprocess → Plan → GenerateLoop → CheckGate → RepairLoop(≤2 轮) → CheckGate → Finalize`。
3. **Plan 阶段**：JSON 输出模式、1 次重试、确定性校验（文件数 3-40、相对路径、README + 依赖声明 + tests/ 必含、交付物全覆盖）；校验失败退化为**确定性兜底计划**（由交付物+组件映射）。
4. **Generate/Repair 阶段**：thinking disabled、7 个工具（write_file / write_files / read_file / list_files / run_check / complete / fail）、最多 30 步、支持取消。
5. **配置**：持久化到 `%APPDATA%\CodeAgent\config.json`；API Key 只存内存 + 支持 `DEEPSEEK_API_KEY` 环境变量，不落盘。
6. **安全**：所有写路径必须是工作区内的相对路径（拒绝 `..`、盘符、绝对路径）；run_check 按 argv 解析 + 命令形态白名单 + `shell=False`（模型输出字符串不进 Shell）；单文件/总量写上限；每次任务在输出目录下创建独立子目录 `generated_<时间戳>/`，不移动用户已有文件。

## 五、遗留风险

- `reasoning_effort` 参数若被网关拒绝，客户端已做 400 降级重试（去掉该参数再发一次）。
- thinking 在 Generate 阶段强制 disabled 会牺牲推理质量换取工具调用稳定性和 temperature 生效——已实测工具调用正常，属必要取舍。
- 生成完整项目的 LLM 调用次数较多（约 10-30 次），GUI 需显示进度与用量。
